1. Overview: 2,000 source records and 518 explicit failed-password records. Explain 23 IPs and 63 usernames. The leading IP has 286 records, 55.2% of explicit records.
2. Click Open the leading-address case. Investigation selects that IP and shows 286. Add root in the shared username filter and show 276. Read an original message. Enter a short observation and download the report.
3. Reset all filters. Open Pattern analysis: use the time heatmap to compare activity timing. Switch to Address and username flow; explain that width counts records and that smaller categories are grouped. Optionally show Address profiles or compare the leading two addresses on the same timeline.
4. Open Evidence. Select the leading IP and root again; search a literal message fragment. Download matching CSV and filter details. Table and export use the same subset.
5. Open Classroom. Explain the proposed school pilot, worksheet, and formative quiz. Classroom uses the full sample independently of filters. Do not claim a completed user study.
6. Methodology: show the 518/518 parser result and separate repeat summaries. Conclude that the tool supports traceable investigation, not automated attack attribution.

No Kali, Ubuntu, or Wazuh experiment is part of this project. The final presentation should describe the implemented Loghub analysis and classroom features accurately.
